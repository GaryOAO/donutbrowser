# Roxy 功能对标与 Donut Parity 路线图

> 目标：按模块评估 Donut Browser 对 Roxy 常见能力的覆盖度，明确 `已有 / 部分 / 缺失`，并给出可量化验收标准，拆分为 MVP 与 V2 两阶段，避免一次性大而全交付。

## 评估口径

- **能力证据来源**：
  - 后端命令注册：`src-tauri/src/lib.rs`（Tauri `generate_handler!`）
  - 前端可见入口：`src/components/`（代理、扩展、同步、分组、批量操作等）
  - 领域实现：`src-tauri/src/profile/`、`src-tauri/src/proxy_manager.rs`、`src-tauri/src/sync/`
- **状态定义**：
  - **已有**：核心流程可在 UI + 命令层闭环完成，满足可上线最小可用。
  - **部分**：已有底座或局部能力，但在规模化、可观测、权限治理、自动化编排上不完整。
  - **缺失**：当前缺少可用链路（命令/UI/数据模型均不足）。

---

## 1) 指纹配置（Fingerprint）

**状态：部分**

### 现状
- 已有 Camoufox / Wayfern 双引擎配置与更新命令（`update_camoufox_config`, `update_wayfern_config`）。
- 已有指纹样本生成（`generate_sample_fingerprint`）。
- Profile 模型已承载 `camoufox_config` / `wayfern_config`、OS 信息等字段。

### 缺口
- 缺“策略模板化”与“批量一致性校验”（例如同组配置漂移检测）。
- 缺“指纹质量评分/冲突检测”可视化（仅有配置，不等于可治理）。

### 验收标准（量化）
1. 支持**至少 20 个关键指纹字段**的模板保存与复用（UA、时区、语言、分辨率、WebGL、Canvas 等）。
2. 批量应用模板到 100 个 Profile，任务成功率 **>= 99%**，失败项可重试。
3. 增加配置漂移检测：每次批量下发后输出“变更/未变更/冲突”三类统计，覆盖率 **100%**。

---

## 2) 批量账号 / 批量资料管理

**状态：部分**

### 现状
- 已有批量删除、批量分组、批量代理分配等动作（命令与组件层存在）。
- Profile 支持标签、备注、分组、代理/VPN 绑定等元数据。

### 缺口
- 缺“批量导入账号资产（账号密码/Cookie/业务标签）的统一流水线”。
- 缺“批量任务中心”（进度、失败原因、重试、回滚）。

### 验收标准（量化）
1. 提供 CSV/JSON 批量导入：单次导入 **>= 5,000** 条账号元数据，成功率 **>= 99.5%**。
2. 批量动作提供 JobID，支持查询进度；状态粒度至少：`pending/running/success/failed/canceled`。
3. 失败项支持按错误类型重试，重试后总体成功率提升 **>= 50%**（相对首次失败集合）。

---

## 3) 代理池（Proxy Pool）

**状态：部分（偏强）**

### 现状
- 已有代理 CRUD、有效性检测、缓存结果、导入导出、TXT 解析、云代理字段等。
- Profile 可绑定代理，支持动态代理 URL/地理信息字段。

### 缺口
- 缺“池化调度策略”（轮换、权重、失败熔断、冷却时间）。
- 缺“健康度看板”（成功率、延迟分位数、区域可用率）。

### 验收标准（量化）
1. 支持至少 3 种调度策略：`round-robin / weighted / sticky`。
2. 代理健康检测可配置周期（最小 30s），连续失败熔断阈值可配（默认 3 次）。
3. 提供过去 24h 可用率指标：每个代理至少输出 `success_rate`, `p95_latency`, `last_error`。

---

## 4) 自动化（Automation）

**状态：部分**

### 现状
- 已有 API Server / MCP Server 启停与状态命令。
- 存在 launch hook、URL 打开、会话级同步等能力，可作为自动化底座。

### 缺口
- 缺“标准化自动化任务编排层”（触发器、步骤、重试、超时、并发控制）。
- 缺“任务运行日志 + 工件归档（截图/网络日志）”。

### 验收标准（量化）
1. 提供 Workflow 模型：支持不少于 **5 种步骤类型**（启动资料、打开URL、执行脚本、等待条件、导出结果）。
2. 每个 Workflow 运行必须产出结构化日志，字段完整率 **100%**（run_id、step、耗时、结果码）。
3. 并发运行 50 个任务时，调度失败率 **< 1%**。

---

## 5) 扩展管理（Extensions）

**状态：已有**

### 现状
- 已有扩展 CRUD、图标获取、扩展分组 CRUD、扩展组分配到 Profile。
- 前端已有扩展管理与扩展组分配对话框。

### 仍可增强点
- 缺扩展版本钉住策略、批量升级窗口、风险扩展告警。

### 验收标准（量化）
1. 在 100 个 Profile 上完成扩展组分配，成功率 **>= 99%**。
2. 单个扩展的安装/更新/删除动作，P95 完成时间 **< 3s**（不含下载）。
3. 扩展清单导出可追溯（名称、版本、来源、分组）覆盖率 **100%**。

---

## 6) 同步（Sync）

**状态：已有（核心）**

### 现状
- 已有 profile/proxy/group/vpn/extension/extension-group 多实体同步开关与状态控制。
- 支持 E2E 密码（设置/检查/删除）、同步计数、全量启用。
- Profile 与 Proxy 模型均带 `sync` 相关字段。

### 缺口
- 多端冲突解决策略与可视化仍可增强（尤其是团队并发编辑场景）。

### 验收标准（量化）
1. 6 类实体同步覆盖率 **100%**（Profile/Proxy/Group/VPN/Extension/ExtensionGroup）。
2. 跨两台设备在 10,000 条实体变更下最终一致性时间 P95 **< 120s**。
3. E2E 开启后，明文敏感字段落盘扫描为 **0 命中**。

---

## 7) 团队协作（Team Collaboration）

**状态：部分**

### 现状
- 已有 team lock 查询能力（`get_team_locks`, `get_team_lock_status`）。
- 已有同步会话/follower 控制（synchronizer 命令）。

### 缺口
- 缺角色权限模型（Owner/Admin/Operator/Viewer）。
- 缺审批流、共享空间、操作归属与冲突仲裁 UI。

### 验收标准（量化）
1. RBAC 至少 4 角色，权限点覆盖核心资源（Profile/Proxy/Sync/Automation）。
2. 权限校验误放行率 **0**（基于集成测试用例集）。
3. 团队场景下冲突编辑可追踪率 **100%**（谁在何时改了什么）。

---

## 8) 日志审计（Audit & Compliance）

**状态：缺失**

### 现状
- 当前更偏技术日志与状态回传，缺产品化“审计日志域模型”。

### 缺口
- 缺不可抵赖审计记录（操作者、对象、前后值摘要、来源IP、客户端、时间戳、签名）。
- 缺按对象/人/时间维度检索与导出；缺保留策略与合规配置。

### 验收标准（量化）
1. 关键动作（创建/修改/删除/授权/同步策略变更）审计覆盖率 **100%**。
2. 检索性能：近 30 天 100 万条日志，组合筛选 P95 响应 **< 2s**。
3. 审计日志防篡改：链式哈希或签名校验失败检测率 **100%**。

## 分阶段范围建议

## Phase 1 — MVP（必须）

目标：先把“可卖、可用、可运维”的闭环搭起来，优先支持中小团队规模化使用。

### 范围（必须交付）
1. **指纹配置基础治理**：模板化 + 批量应用 + 漂移报告。
2. **批量任务中心 v1**：导入、批量分配、进度跟踪、失败重试。
3. **代理池 v1**：基础调度（RR/加权）、健康检查、熔断。
4. **自动化 v1**：API/MCP 基础上补工作流执行框架（最少 5 步骤类型）。
5. **同步稳态强化**：冲突提示与恢复向导（先做最小闭环）。
6. **团队协作最小化**：角色权限（至少 2~3 角色）+ 关键资源访问控制。

### MVP 出口标准（Go/No-Go）
- Top 6 核心场景（建资料、分配代理、批量启动、同步、扩展组下发、自动化运行）端到端通过率 **>= 95%**。
- 50 并发自动化任务与 10k 级数据量下，核心接口错误率 **< 1%**。
- P0/P1 缺陷清零。

## Phase 2 — V2（可选）

目标：从“能用”升级到“可治理、可审计、可企业化扩展”。

### 范围（可选增强）
1. 指纹质量评分、规则引擎、异常指纹告警。
2. 代理池高级策略：Sticky 会话、地域/ISP 自适应、成本优化路由。
3. 自动化高级编排：条件分支、回滚节点、外部事件触发器。
4. 团队协作企业化：完整 RBAC、审批流、共享工作区、SSO 对接。
5. **日志审计全量能力**：防篡改、检索、导出、保留策略、合规报表。

### V2 出口标准
- 审计覆盖核心操作 **100%**。
- 多团队隔离与权限回归测试通过率 **100%**。
- 关键管理视图（代理健康/同步冲突/审计检索）P95 响应达到设定 SLA。

---

## 实施顺序建议（降低风险）

1. 先做 **MVP 数据模型与任务框架**（批量任务、自动化任务、审计事件骨架）。
2. 再做 **代理池与指纹治理**（与现有 profile/proxy 结构耦合最深，优先稳定）。
3. 然后做 **团队权限最小集**（先保护高风险动作）。
4. 最后进入 **V2 的审计与企业化扩展**。

这样可以保证：每一阶段都有可验证业务价值，不会因为“全量功能同时推进”导致范围失控。
